Supabase設定項目
作成日: 2026-04-29

このファイルは、公開Supabase側でユーザーが手動確認・設定する項目をまとめるものです。
リポジトリ内のコードやSQLを変更した場合は、このファイルも必要に応じて追記してください。

新規の空プロジェクトにまとめて作る場合だけ、supabase/schema.sql を使ってください。
既存プロジェクトに schema.sql と migrations を両方そのまま流すと、重複や意図しない上書き確認が増えるため避けてください。

2. anon権限の最小範囲

anonには、公開フォームに必要なselect/insert/RPCだけを許可します。
手動で broad grant を追加しないでください。

許可してよい範囲:
- scoring_configs: 公開中の配点設定をselect
- material_points: 有効な原料ポイントをselect
- reservation_slots: 公開中の予約枠をselect
- admin_settings: is_public = true の公開設定をselect
- fragrance_products: QR公開対象の商品名だけselect
- product_qr_codes: 公開中QRの識別に必要な列だけselect
- qr_product_requests: QR作成依頼のinsertのみ
- questionnaire_results: create_questionnaire_result RPC、および必要列のinsert
- questionnaire_results: update_questionnaire_result_by_token RPCによる本人トークン付き限定更新
- reservations: create_public_reservation RPC、および必要列のinsert
- reservations: fetch_reservation_by_code RPCによる予約コード付き限定参照

anonに許可しない範囲:
- customers
- staff_profiles
- workshop_sessions
- notification_events
- email_events
- fragrance_products の個人情報・レシピ・同意情報
- qr_product_requests のselect/update/delete
- 管理者・スタッフ向けの全件select/update/delete

既存Supabaseに過去検証用の broad policy / broad grant が残っている場合は削除してください。
特に anon に対する all / update / delete / notification_events select / email_events select は残さないでください。

3. Supabase Auth のスタッフ/管理者アカウント

スタッフ/管理者はSupabase Authで正式に作成してください。
フロント側の管理者設定画面に残るスタッフID/パスワード保存は、現時点では運用補助・旧互換の要素が残るため、正式な認証情報の正本にしないでください。

2026-04-29追記:
管理者設定画面では、スタッフ/管理者パスワードを admin_settings.staff_directory に保存しない方針へ変更しました。
既存Supabaseに過去データとして staffPassword / managerPassword が残っている場合は、SQL Editorで以下を実行して削除してください。

update public.admin_settings
set
  setting_value = coalesce(
    (
      select jsonb_agg(
        item
          - 'staffPassword'
          - 'staff_password'
          - 'managerPassword'
          - 'manager_password'
      )
      from jsonb_array_elements(setting_value) as item
    ),
    '[]'::jsonb
  ),
  updated_at = now()
where setting_key = 'staff_directory'
  and jsonb_typeof(setting_value) = 'array';

このSQLはAuthユーザーやstaff_profilesは作成しません。
スタッフ/管理者アカウントは、引き続きSupabase Auth側で作成してください。

Authユーザー作成後、以下のどちらかにロールを設定してください。
- app_metadata.portal_role = "staff" または "manager"
- app_metadata.role = "staff" または "manager"

2026-04-29追記:
権限判定では user_metadata.portal_role / user_metadata.role を参照しない方針へ変更しました。
スタッフ/管理者のロールは必ず app_metadata に設定してください。
"admin" はコード側で "manager" に正規化されますが、新規作成時は "manager" を使ってください。

ログインIDをメールアドレスではなくID形式で入力する運用では、現在のコードは次のメールに変換します。
- staff_a -> staff_a@staff.portal.fragrance.local
- manager_a -> manager_a@manager.portal.fragrance.local

そのため、Authユーザーのemailは上記の変換後メールに合わせるか、ログイン欄には実メールアドレスを入力してください。

4. staff_profiles の作成・紐づけ

Authユーザーを作っただけでは、スタッフ画面で接客記録やQR対応を安全に保存できません。
public.staff_profiles に対応する行を作り、auth_user_id にSupabase AuthユーザーIDを設定してください。

最低限必要な値:
- staff_name
- display_name
- role: "staff" または "manager"
- auth_user_id: Supabase AuthユーザーID
- is_active: true

manager権限でスタッフ登録・編集する場合も、Authユーザーとstaff_profilesの紐づきが正しいか確認してください。

4-2. 会員アカウント

会員は customer/customer-login.html から Supabase Auth の signUp / signIn を使います。
初回パスワード設定時、メール確認が不要なSupabase設定では customers 行も同時に作成します。
メール確認が必要なSupabase設定では、確認後のログイン時に customers 行を作成します。

確認すること:
- Supabase Auth の Email provider が有効
- メール確認を必須にするかどうかの運用
- 確認メールの送信元/テンプレート
- customers.auth_user_id が Auth user id と一致している

QR第三者は会員ではないため、customer/customer-login.html へ誘導しないでください。

5. 公開設定 admin_settings

公開サイトに出してよい設定だけ、admin_settings.is_public = true にしてください。
店舗内部設定や管理者用設定は is_public = false にしてください。

QR商品作成依頼ページでは、以下のsetting_keyを使います。
- qr_product_public_settings

想定するsetting_value:
- price_10ml
- price_30ml
- max_volume_ml
- shop_phone
- business_hours

上記は管理者設定画面から保存できますが、公開Supabaseへ初回反映した直後は値が存在するか確認してください。

6. メール送信

現時点ではメール実送信は行いません。
QR作成依頼受付時に email_events へ送信予定イベントを queued として記録するところまでです。

設定しないこと:
- フロントエンドから直接メールAPIを呼ばない
- service_role key を js/supabase-config.js やHTMLに置かない
- メールAPIキーを公開リポジトリや公開Supabaseのanon操作に混ぜない

後続フェーズで決めること:
- Edge Functions の関数名
- メールAPIプロバイダ
- 送信元メールアドレス/ドメイン
- 失敗時の再送・手動対応ルール
- 送信ログの保持期間

7. 個人情報保持・削除方針

初期実装では自動削除処理はまだ入れません。
削除・匿名化対象を判別できる列をSupabaseに持たせる段階です。

QR依頼者メール:
- qr_product_requests.email_retention_until
- email_events.retention_until
- 発送完了または期限切れから6か月後に削除または匿名化する想定

発送先住所:
- qr_product_requests.shipping_address_retention_until
- 発送完了から3か月後に削除またはマスクする想定
- 発送先入力・発送完了操作は次フェーズのため、現時点では運用開始しないでください。

注文・成果集計:
- 個人情報を含めずに保持する方針です。

8. QR導線で混ぜてはいけないこと

QR第三者は customers に入れません。
QR依頼は qr_product_requests にだけ保存します。

旧QRページや旧互換ページは、新しい product_qr_codes / fragrance_products 導線へ混ぜないでください。
旧ページを残す必要がある場合は archived/legacy/ に隔離します。

9. 公開キーと秘密キー

js/supabase-config.js に置いてよいのは、Supabase URL と anon public key だけです。
service_role key、SMTPキー、メールAPIキー、管理者用の秘密値は絶対に置かないでください。

10. ユーザー側チェックリスト

- SQLを上記順番で適用した
- 古いSQLやarchive内SQLを実行していない
- anonに広い権限を付けていない
- Authにスタッフ/管理者ユーザーを作成した
- Authユーザーの app_metadata に portal_role / role を設定した
- staff_profiles.auth_user_id をAuthユーザーIDに紐づけた
- 既存 admin_settings.staff_directory に staffPassword / managerPassword が残っていない
- qr_product_public_settings を確認した
- js/supabase-config.js に公開URLとanon keyだけを設定した
- service_role keyやメールAPIキーをフロントに置いていない
- QR第三者を customers に入れない運用を確認した
