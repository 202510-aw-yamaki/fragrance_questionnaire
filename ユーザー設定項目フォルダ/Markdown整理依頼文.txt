Markdown整理が必要になった場合は、以下の文面でユーザー確認を取ること。

現在の作業では、ページレイアウト再構築にあたり、古い実装メモや現行仕様と重複する Markdown が作業ノイズになる可能性があります。

ただし、既存 Markdown には過去の判断や仕様変更の経緯が含まれるため、削除や全面更新は行いません。

整理する場合は、以下の方針で進めてよいか確認してください。

1. 現行仕様の正本は `docs/00_PROJECT_CORE.md` から `docs/06_OPEN_ISSUES.md` を優先する。
2. 古くなった作業ログや過去指示は削除せず、必要に応じて `docs/archive/` へ移す。
3. `docs/SPEC.md`、`docs/SURVEY_SCORING_LOGIC.md`、`docs/MATERIAL_POINTS.md` は役割が残るため、統合や更新が必要な箇所だけを限定して扱う。
4. 仕様変更を書く場合は元記述を残し、その後に「どの要望で変更したか」が分かる追記を行う。
5. チェックリストがある場合は、元の作業文を変えず、完了後にチェックを入れ、次の行に「→」で対応内容を追記する。
6. 文字化けが疑われる箇所は、PowerShell出力だけで判断せず、対象箇所を提示してユーザー診断を受けてから扱う。

この方針で Markdown 整理を進めてよいでしょうか。
