2. スタッフ/管理者Auth

スタッフ/管理者ユーザーはSupabase Authで作成してください。
権限は user_metadata ではなく app_metadata に設定してください。

設定例:
- app_metadata.portal_role = "staff" または "manager"
- app_metadata.role = "staff" または "manager"

"admin" はコード上 manager として扱えますが、新規作成では "manager" を使ってください。

ログインID運用の場合、現在のコードは以下のメールへ変換します。
- staff_a -> staff_a@staff.portal.fragrance.local
- manager_a -> manager_a@manager.portal.fragrance.local

Authユーザーのemailをこの形式に合わせるか、ログイン欄へ実メールアドレスを入力してください。

3. staff_profiles

スタッフ/管理者Authユーザー作成後、public.staff_profiles に対応行を作成してください。

最低限必要な値:
- staff_name
- display_name
- role: "staff" または "manager"
- auth_user_id: Supabase AuthユーザーID
- is_active: true

staff-customer-detail.html の保存、予約枠担当、QR成果集計は staff_profiles.auth_user_id の紐づきを前提にします。

4. 既存staff_directoryのパスワード削除

管理者設定画面では、staff_directory にスタッフ/管理者パスワードを保存しない方針です。
既存Supabaseに過去データとして staffPassword / managerPassword が残っている場合は、SQL Editorで以下を実行してください。

update public.admin_settings
set
  setting_value = coalesce(
    (
      select jsonb_agg(
        item
          - 'staffPassword'
          - 'staff_password'
          - 'managerPassword'
          - 'manager_password'
      )
      from jsonb_array_elements(setting_value) as item
    ),
    '[]'::jsonb
  ),
  updated_at = now()
where setting_key = 'staff_directory'
  and jsonb_typeof(setting_value) = 'array';

5. 会員Auth

会員は customer/customer-login.html から Supabase Auth signUp / signIn を使います。
Email provider を有効にし、確認メールを必須にするか運用確認してください。

確認すること:
- Supabase Auth の Email provider が有効
- 確認メールの送信元/テンプレート
- メール確認必須の場合、確認後ログイン時に customers 行が作られること
- メール確認不要の場合、初回設定時に customers 行が作られること
- customers.auth_user_id が Auth user id と一致していること

スタッフ/管理者 app_metadata を持つAuthユーザーは、会員ページでは customers に入れない方針です。
QR第三者も会員ではないため、customers には入れません。

6. anon権限

anonには公開フォームに必要なselect/insert/RPCだけを許可します。
notification_events、email_events、customers、staff_profiles へanon権限を追加しないでください。

公開QR依頼では、DB側でも以下を制限します。
- メール形式
- 最大依頼容量
- QR有効期限
- QR公開状態
- 完成品公開状態

7. QR公開設定

admin_settings の qr_product_public_settings は公開行として is_public = true にしてください。

想定するsetting_value:
- price_10ml
- price_30ml
- max_volume_ml
- shop_phone
- business_hours

8. メール送信

現時点ではメール実送信は行いません。
QR作成依頼受付時に email_events へ queued イベントを作成するところまでです。

設定しないこと:
- フロントエンドから直接メールAPIを呼ばない
- service_role key を js/supabase-config.js やHTMLに置かない
- メールAPIキーを公開リポジトリに置かない

Edge Functions、メールAPI、送信元、再送、失敗時運用、送信ログ保持は後続フェーズで決めます。
