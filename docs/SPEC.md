# SPEC

本書は、今後このリポジトリで目標とする仕様の固定書です。  
配点設計と原料プロファイル設計の正本は `deep-research-report.md` とし、実装の進捗管理は `COMPLETED_REQUIREMENTS.md` / `UNMET_REQUIREMENTS.md` で行います。

## 正本の考え方

- 配点ロジックと原料プロファイルの基準は `deep-research-report.md`
- 目標仕様の整理先は `docs/SPEC.md`、`docs/IMPLEMENTATION_RULES.md`、`docs/SURVEY_SCORING_LOGIC.md`、`docs/MATERIAL_POINTS.md`
- 実装済み / 未達の状態管理は `docs/COMPLETED_REQUIREMENTS.md`、`docs/UNMET_REQUIREMENTS.md`
- 現行コードが仕様書と異なる場合は、原則としてコード側が未追従とみなす

## システムの到達目標

- 顧客側は現状のフロント導線を大きく崩さず使えること
- 店舗スタッフが IT に強くなくても、予約枠作成、予約確認、来店前準備、ワークショップ結果登録、レシピ登録まで扱えること
- 店舗管理者が、スタッフ権限、基剤、原料、将来のテンプレート拡張を管理できること
- バックエンドは Supabase を使用すること
- 再注文時に過去レシピと五軸グラフを参照でき、蓄積結果を将来のおすすめテンプレートへ反映できること

### ログイン導線

- ログイン画面は 1 ページ内で `staff` 用と `manager` 用の 2 面構成にする
- `staff` 側はスタッフ ID / パスワード、`manager` 側は管理者 ID / パスワードでログインする
- `staff` ログイン後の基本導線は「スタッフ確認ページ -> 予約枠作成ページ または 予約情報一覧ページ -> 予約顧客情報詳細ページ」とする
- `manager` ログイン後の基本導線は「管理スタッフ確認ページ -> スタッフ登録/管理、配点ロジック、原料ポイント」とする

### スタッフ画面

- スタッフ確認ページは、本日の予定確認、向こう一週間の予約件数、向こう二週間の予約未作成日を 1 画面で確認できること
- スタッフ確認ページから遷移する予約一覧の名称は「予約情報一覧ページ」で統一する
- 予約枠作成ページは、予約枠一覧、単件の新規作成 / 編集、入力中または選択中の枠プレビュー、一括作成を 1 画面で扱う
- 予約情報一覧ページは、日付、予約情報状態、キーワードで絞り込みできること
- 予約情報一覧ページの一覧には、来店日時、お客様名、来店目的、人数、傾向、作成日時、予約情報、詳細を表示する
- 予約コードは予約情報一覧ページでは露出せず、内部データとして保持する
- 予約情報一覧ページの詳細導線は、予約顧客情報詳細ページへ遷移するリンクボタンとする
- 予約顧客情報詳細ページは、お客様情報、アンケート回答、5 軸比較、ヒアリング内容、おすすめ原料、最終原料登録、お客様の感想、QR 表示を 1 画面で扱う
- 最終原料登録は、原料プルダウン選択と割合スピンボタン入力で扱い、必要に応じて 100% へ整える補助操作を持つ

### 管理者画面

- 管理スタッフ確認ページは、本日の出勤状況、翌週の予約件数 / 枠数、向こう二週間の予約枠確認、配点ロジック重み、分岐テンプレート、原料クイックリンクをまとめて確認できること
- 管理スタッフ確認ページの「アンケート編集」は、現状では独立ページを増やさず、配点ロジックページへの導線として扱う
- 管理スタッフ確認ページの原料一覧ボタンは、原料ポイントページ内の対象原料へ自動スクロールする

### スタッフ登録 / 管理

- スタッフ登録 / 管理ページは、本日の出勤者一覧、スタッフ登録 / 編集導線、スタッフ出勤管理導線、向こう一週間のスタッフカレンダー表を持つ
- スタッフ新規登録は登録モーダルを開く
- スタッフ基本編集は個別出勤モーダルを開く
- スタッフ出勤管理は、登録済みスタッフをプルダウンから選択し、対象スタッフの保存済み内容を読み込んだ登録モーダルを開く
- 個別出勤モーダルは日付単位で出勤 / 退勤 / 休みを設定し、「翌週も追加で表示する」で翌週分を拡張表示できる
