# SPEC

本書は、今後このリポジトリで目標とする仕様の固定書です。  
配点設計と原料プロファイル設計の正本は `deep-research-report.md` とし、実装の進捗管理は `COMPLETED_REQUIREMENTS.md` / `UNMET_REQUIREMENTS.md` で行います。

## 正本の考え方

- 配点ロジックと原料プロファイルの基準は `deep-research-report.md`
- 目標仕様の整理先は `docs/SPEC.md`、`docs/IMPLEMENTATION_RULES.md`、`docs/SURVEY_SCORING_LOGIC.md`、`docs/MATERIAL_POINTS.md`
- 実装済み / 未達の状態管理は `docs/COMPLETED_REQUIREMENTS.md`、`docs/UNMET_REQUIREMENTS.md`
- `レイアウトimg` 配下の画像は、主にスタッフ / 管理者画面の導線、画面構成、ラベル、モーダル構成を補う参考資料として扱う
- `レイアウトimg` 配下の画像内にある数値はモック値を含み得るため、配点値、5軸値、テンプレート値、原料ポイント値の正本としては扱わない
- 数値仕様が必要な場合は、必ず `deep-research-report.md`、`docs/SURVEY_SCORING_LOGIC.md`、`docs/MATERIAL_POINTS.md` を参照する
- 現行コードが仕様書と異なる場合は、原則としてコード側が未追従とみなす

## システムの到達目標

- 顧客側は現状のフロント導線を大きく崩さず使えること
- 店舗スタッフが IT に強くなくても、予約枠作成、予約確認、来店前準備、ワークショップ結果登録、レシピ登録まで扱えること
- 店舗管理者が、スタッフ権限、基剤、原料、将来のテンプレート拡張を管理できること
- バックエンドは Supabase を使用すること
- 再注文時に過去レシピと五軸グラフを参照でき、蓄積結果を将来のおすすめテンプレートへ反映できること

## 追記: 2026-04-19 スタッフ用レイアウト画像に基づく画面要件補足

この追記は `レイアウトimg` 配下のスタッフ用レイアウト画像確認を受けて、現行の固定仕様へ不足していた画面要件を補うために追加する。

### ログイン導線

- ログイン画面は 1 ページ内で `staff` 用と `manager` 用の 2 面構成にする
- `staff` 側はスタッフ ID / パスワード、`manager` 側は管理者 ID / パスワードでログインする
- `staff` ログイン後の基本導線は「スタッフ確認ページ -> 予約枠作成ページ または 予約情報一覧ページ -> 予約顧客情報詳細ページ」とする
- `manager` ログイン後の基本導線は「管理スタッフ確認ページ -> スタッフ登録/管理、配点ロジック、原料ポイント」とする

### スタッフ画面

- スタッフ確認ページは、本日の予定確認、向こう一週間の予約件数、向こう二週間の予約未作成日を 1 画面で確認できること
- スタッフ確認ページから遷移する予約一覧の名称は「予約情報一覧ページ」で統一する
- スタッフ確認ページのカレンダーUIは、以下の作成文言を正として扱う
  - 日表示のカレンダーUIを作成する
  - 1日のタイムライン表示とする
  - 左側に時間ラベル（09:00〜18:00）を表示する
  - 右側にイベント詳細を表示し、予約枠と対応づける
  - 昼休憩時間帯はアイコン付きで表示する
  - イベントには時間（開始時間-終了時間）、タイトル、場所、参加人数を表示する
  - `.day-view` はメインコンテナとし、マックス width は左半分を基準とする
  - `.day-timeline` はタイムライン全体を表す
  - `.day-hour` は 1 時間の行とし、`display: flex`、`min-height: 60px` を前提とする
  - `.day-hour-label` は時間ラベルとし、そのイベントの時間をまたがって表示する
  - `.day-hour-content` はイベント表示エリアとする
  - `.day-event` はイベントカードとし、カラークラスは `primary` / `success` / `warning` / `danger` を持てること
  - イベントカードは `border-left: 4px solid` で色分けし、背景色はカラーに応じた薄い色を使う
  - `.day-event-time` は時間範囲を表示する
  - `.day-event-title` はイベント名を表示する
  - `.day-event-location` は場所をアイコン付きで表示する
  - `.day-event-attendees` は参加者アバターを表示する
  - ナビゲーションとして前日 / 翌日ボタンと日付表示を持つ
- 予約枠作成ページは、予約枠一覧、単件の新規作成 / 編集、入力中または選択中の枠プレビュー、一括作成を 1 画面で扱う
- 予約情報一覧ページは、日付、予約情報状態、キーワードで絞り込みできること
- 予約情報一覧ページの一覧には、来店日時、お客様名、来店目的、人数、傾向、作成日時、予約情報、詳細を表示する
- 予約コードは予約情報一覧ページでは露出せず、内部データとして保持する
- 予約情報一覧ページの詳細導線は、予約顧客情報詳細ページへ遷移するリンクボタンとする
- 予約顧客情報詳細ページは、お客様情報、アンケート回答、5 軸比較、ヒアリング内容、おすすめ原料、最終原料登録、お客様の感想、QR 表示を 1 画面で扱う
- 最終原料登録は、原料プルダウン選択と割合スピンボタン入力で扱い、必要に応じて 100% へ整える補助操作を持つ

### 管理者画面

- 管理スタッフ確認ページは、本日の出勤状況、翌週の予約件数 / 枠数、向こう二週間の予約枠確認、配点ロジック重み、分岐テンプレート、原料クイックリンクをまとめて確認できること
- 管理スタッフ確認ページの「アンケート編集」は、現状では独立ページを増やさず、配点ロジックページへの導線として扱う
- 管理スタッフ確認ページの原料一覧ボタンは、原料ポイントページ内の対象原料へ自動スクロールする

### スタッフ登録 / 管理

- スタッフ登録 / 管理ページは、本日の出勤者一覧、スタッフ登録 / 編集導線、スタッフ出勤管理導線、向こう一週間のスタッフカレンダー表を持つ
- スタッフ新規登録は登録モーダルを開く
- スタッフ基本編集は個別出勤モーダルを開く
- スタッフ出勤管理は、登録済みスタッフをプルダウンから選択し、対象スタッフの保存済み内容を読み込んだ登録モーダルを開く
- 個別出勤モーダルは日付単位で出勤 / 退勤 / 休みを設定し、「翌週も追加で表示する」で翌週分を拡張表示できる

## 追記: 2026-04-19 ユーザー文言による補正

この追記は、レイアウト画像の読み取りだけでは誤差が出る箇所について、ユーザーから直接受けた文言を優先するために追加する。

### スタッフ確認ページ

- スタッフ確認ページは、ログイン時に割り当てられた担当スタッフごとの画面として扱う
- スタッフ確認ページの「向こう一週間の予約件数」は、そのスタッフに割り当てられた向こう一週間の予約獲得件数を表示する
- スタッフ確認ページの「予約枠未作成日」は、そのスタッフの休日 / 非出勤日を除いた上で、予約枠が未作成の日付だけを表示する

### 予約枠作成ページ

- 一括作成時に、すでに登録済みの日付が含まれる場合は、対象日ごとに「mm/dd は登録が既にしてあります」と分かるポップアップを表示する方針を正とする

### 予約顧客情報詳細ページ

- 5軸グラフ比較は、左を「アンケート回答時」、右を「予約完了時」とする
- 5軸グラフ比較は、画面間の一時引き継ぎではなく、DB に保管済みのデータを読み込んで表示する
- 顧客情報として保存する項目は、お客様名、メールアドレス、電話番号（任意）とする
- 顧客情報の保存時はモーダルを開き、同意を得た上で保存する
- 予約顧客情報詳細ページは、お客様と対面で会話しながら、ヒアリング内容や各入力項目を直接記録していく運用を正とする
- 最終登録後は QR コードを発行できることを正とする

### 将来拡張

- QR コードの遷移先は、将来のお客様専用 TOP ページを想定し、現在の `index.html` とは別ページとする
- QR コードをお客様のメールアドレスへ送る機能は、現時点では必須ではなく将来拡張として扱う
