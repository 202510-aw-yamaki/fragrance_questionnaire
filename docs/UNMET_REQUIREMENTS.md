# UNMET_REQUIREMENTS

本書は、目標仕様に対して現在まだ未達の項目だけを記録する文書です。  
達成した項目は、本書から削除して `COMPLETED_REQUIREMENTS.md` へ移します。

## `deep-research-report.md` への実装追従

- 現行コードの暫定ロジックと、研究レポート基準のロジック差分を解消する

## 店舗スタッフ機能

- スタッフ向けログイン後画面を、業務フロー単位で整理する
- 出勤シフトに応じた予約枠作成フローを用意する
- 予約状況確認と来店前準備がしやすい画面を用意する
- 顧客の事前アンケート回答と五軸を確認しながら接客できる画面を用意する
- 店舗で対話後に確定した最終五軸グラフの入力画面を用意する
- 最終商品に使用した基剤 / 原料 / 割合 / ロットの登録画面を用意する
- スタッフが JSON を直接触らずに操作できる UI にする

## 店舗管理者機能

- `staff` と `manager` の権限分離を実装する
- 店舗管理者がスタッフ権限を登録 / 編集できるようにする
- 基剤管理画面を独立させる
- 原料管理画面を独立させる
- 基剤 / 原料のテンプレート種類追加を扱えるようにする
- 基剤 / 原料の数値をスピンボタンで微調整できるようにする

## データモデル拡張

- `customer_id` を軸に、予約、アンケート、来店結果、再注文を束ねる
- 五軸グラフを次の 3 段階で保持する
  - アンケート後
  - 予約時
  - 店舗調整後
- 最終五軸とレシピを強く紐付ける
- レシピに基剤 / 原料 / 割合 / ロット / 商品種を保持する
- `material_points` に `material_type = base | ingredient` を持たせた運用へ寄せる

## レシピ・再注文・おすすめテンプレート

- 再注文時に過去レシピを参照できるようにする
- 再注文時に過去の五軸グラフと比較できるようにする
- レシピと五軸の紐付け粒度を上げる
- 再注文実績が増えたものを将来のフロントおすすめテンプレートへ反映できるようにする

## 運用上の未達

- `COMPLETED_REQUIREMENTS.md` と `UNMET_REQUIREMENTS.md` の移行運用を、今後の作業ごとに継続反映する
- 仕様変更時は `SPEC.md`、`SURVEY_SCORING_LOGIC.md`、`MATERIAL_POINTS.md` へ先に反映し、その後コードを追従させる
